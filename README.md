# ИнтеграцияApacheKafka — обмен портала с БП РФ и БП КЗ через Apache Kafka

Расширение 1С:Предприятие для обмена с порталом через Kafka. Два контура: **Бухгалтерия РФ** и **Бухгалтерия Казахстана**. С 1.2.0 обмен охватывает контрагентов, номенклатуру и счета на оплату покупателю.

| | |
| --- | --- |
| Версия расширения | `1.2.0` |
| Префикс объектов | `KFK_` |
| Совместимость расширения | 8.3.24+ |
| Транспорт | внешняя компонента [Simple Kafka Adapter](https://github.com/NuclearAPK/Simple-Kafka_Adapter) (в макете `KFK_Компонента`) |
| Контракты | контрагент `1.1.0` (входящие `1.0.*` принимаются), номенклатура `product/1.0.0`, счёт `invoice/1.0.0` |

> Это карточка **публикации**. Исходники расширения и документация ниже — то, что безопасно выкладывать отдельно от типовых конфигураций 1С.

## Возможности

### Портал → 1С (входящий)

- Вход: топик `contragents` (`contragent_created` / `contragent_updated` от `corp`)
- Выход статусов: топик `contragents.exchange` (Started → Completed / Failed)
- Маршрутизация по `organization-id`: `1` → РФ, `5` → КЗ, без заголовка → оба контура
- Inbox до Kafka commit, идемпотентность по `(контур, message id)`, Transactional Outbox статусов
- Полный снимок: карточка, контакты, адреса, банковские счета, договоры

### 1С → портал (исходящий, с v1.1.0)

- При создании карточки пользователем — Outbox `KFK_ИсходящиеСнимки`, публикация в `contragents` как `contragent.created` или прежнее `contragent_created` (`sender` = `1c-rf` / `1c-kz`)
- `uid` = GUID ссылки 1С; задержка публикации (по умолчанию 300 с), чтобы успеть ввести счета и договоры
- Приём статусов портала из `contragents.exchange` (`sender=corp`) и последующий `contragent.updated` с привязкой `id` портала по `uid`
- Исходящий обмен **по умолчанию выключен** (включается в настройках вида объекта)
- Правило владения: **1С только создаёт**, дальше карточкой владеет портал

### Номенклатура (с v1.2.0)

- Портал → 1С: топик `products`, поиск только по `uid`, новый элемент создаётся с GUID = `uid`
- 1С → портал: новый элемент (не группа), созданный не обменом, один раз уходит как `product.created`
- Ставка НДС товара с портала не приходит: её задаёт настройка контура при создании и строка счёта при продаже

### Счета на оплату покупателю (с v1.2.0)

- Портал → 1С: топик `invoices`, номер портала в `KFK_НомерПортала`, номер 1С не подменяется
- Если контрагента или товара ещё нет, счёт ждёт их ограниченное время, затем `REFERENCE_NOT_FOUND`
- Закрытый период не меняется, ответ `PERIOD_CLOSED`
- 1С → портал: новый счёт уходит один раз после `completed` портала по новым контрагенту и товарам
- Виды обмена включаются отдельно. Выключенный вид консьюмер пропускает без ответа порталу

### Общее

- Прямое подключение к брокеру через native-компоненту (без REST-моста)
- Роли сервиса и диагностики, replay failed, метрики, регламентная очистка retention

## Быстрый старт (администратор)

1. Загрузить **свою** поставку `.cfe` из `dist/` (или XML из `cfe-rf/` / `cfe-kz/`) в целевую базу.
2. Создать топики `contragents` и `contragents.exchange` (ACL: 1С — READ+WRITE на оба; отдельная consumer group на статусы портала).
3. Настроить `KFK_Брокеры`, `KFK_НастройкиКонтуров`, `KFK_МаршрутизацияОрганизаций`.
4. Положить пароль Kafka вне git (`KAFKA_PASSWORD` / файл / БСП-хранилище).
5. Включить `KFK_ЗаданиеМониторингаКонсьюмеров` и активный `KFK_Консьюмеры`.
6. При необходимости **включить исходящий обмен** в настройках контура (по умолчанию выключен).
7. Проверить `ПроверитьГотовностьПодключенияKafka` и `Состояние("RF"|"KZ")`.

Подробности — в инструкциях администратора.

## Архитектура (кратко)

```text
Портал ──► Kafka:contragents ──► CFE consumer (simpleKafka1C)
                                      │
                                      ├─ Inbox + commit offset
                                      ├─ Started → contragents.exchange
                                      ├─ адаптер РФ / КЗ (полный снимок)
                                      └─ Completed|Failed → contragents.exchange

Бухгалтер создаёт карточку в 1С
   → Outbox KFK_ИсходящиеСнимки (задержка)
   → Kafka:contragents (contragent_created, sender=1c-rf|1c-kz)
   ← статусы corp в contragents.exchange
   ← contragent_updated с id+uid → привязка KFK_ВнешнийID
```

Типовые конфигурации на поддержке **не правятся**: внешние ключи и транспорт живут в расширении.

## Статус

| Контур | Контрагенты | Номенклатура | Счета покупателю |
| --- | --- | --- | --- |
| РФ | приём и создание из 1С, исходящий выключен по умолчанию | приём и однократная отправка нового товара, вид выключен по умолчанию | приём и однократная отправка нового счёта, вид выключен по умолчанию |
| КЗ | то же | то же, без реквизита страны | то же, счёт только записывается |

## Отказ от ответственности

Решение рассчитано на контролируемые dev/test/prod контуры заказчика. Полный снимок **помечает на удаление** (`ПометкаУдаления`) отсутствующие в сообщении банковские счета и договоры, включая ручные; физически не удаляет. Перед включением на рабочей базе — резервная копия и согласование правила с бизнесом.
