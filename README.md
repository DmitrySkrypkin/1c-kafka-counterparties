# ИнтеграцияApacheKafka — обмен контрагентами с порталом через Apache Kafka

Расширение 1С:Предприятие для приёма полного снимка контрагента из Kafka и публикации статусов обработки. Два контура: **Бухгалтерия РФ** и **Бухгалтерия Казахстана**.

| | |
| --- | --- |
| Версия расширения | `1.0.0` |
| Префикс объектов | `KFK_` |
| Совместимость расширения | 8.3.24+ |
| Транспорт | внешняя компонента [Simple Kafka Adapter](https://github.com/NuclearAPK/Simple-Kafka_Adapter) (в макете `KFK_Компонента`) |
| Контракт снимка | `1.0.0` (JSON Schema + fixtures) |

> Это карточка **публикации**. Исходники расширения и документация ниже — то, что безопасно выкладывать отдельно от типовых конфигураций 1С.

## Возможности

- Вход: топик `contragents` (`contragent_created` / `contragent_updated`)
- Выход: топик `contragents.exchange` (Started → Completed / Failed)
- Маршрутизация по `organization-id`: `1` → РФ, `5` → КЗ, без заголовка → оба контура
- Inbox до Kafka commit, идемпотентность по `(контур, message id)`, Transactional Outbox статусов
- Полный снимок: карточка, контакты, адреса, банковские счета, договоры
- Прямое подключение к брокеру через native-компоненту (без REST-моста)
- Роли сервиса и диагностики, replay failed, метрики, регламентная очистка retention

**Не включать в публичный репозиторий:**

- выгрузки типовых конфигураций (`src/cf`, `src/cf_bp_kz`)
- `.dev.env`, пароли, ACL, адреса внутренних брокеров с credentials
- `memory-bank/` с рабочими явками окружения
- правила доступа с паролями
- протоколы `build/verification/` с данными живых баз (по политике заказчика)

## Быстрый старт (администратор)

1. Загрузить CFE в целевую базу (РФ или КЗ — **своя** поставка).
2. Создать топики `contragents` и `contragents.exchange`.
3. Настроить `KFK_Брокеры`, `KFK_НастройкиКонтуров`, `KFK_МаршрутизацияОрганизаций`.
4. Положить пароль Kafka вне git (`KAFKA_PASSWORD` / файл / БСП-хранилище).
5. Включить `KFK_ЗаданиеМониторингаКонсьюмеров` и активный `KFK_Консьюмеры`.
6. Проверить `ПроверитьГотовностьПодключенияKafka` и `Состояние("RF"|"KZ")`.

Подробности — в инструкциях администратора.

## Архитектура (кратко)

```text
Портал ──► Kafka:contragents ──► CFE consumer (simpleKafka1C)
                                      │
                                      ├─ Inbox + commit offset
                                      ├─ Started → contragents.exchange
                                      ├─ адаптер РФ / КЗ (полный снимок)
                                      └─ Completed|Failed → contragents.exchange
```

Типовые конфигурации на поддержке **не правятся**: внешние ключи и транспорт живут в расширении.

## Отказ от ответственности

Решение рассчитано на контролируемые dev/test/prod контуры заказчика. Полный снимок **удаляет** отсутствующие в сообщении банковские счета и договоры, включая ручные. Перед включением на рабочей базе — резервная копия и согласование правила с бизнесом.
