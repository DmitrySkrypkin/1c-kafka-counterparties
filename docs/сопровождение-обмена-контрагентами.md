# Обмен контрагентами: сопровождение

**Обновлено:** 11.11.2026
**Для кого:** администратор 1С, к которому приходят с вопросами «контрагент не появился», «не ушёл», «пропал счёт».
**Подходит для обеих баз**, РФ и КЗ. Где значения различаются, указаны оба.
**Связанные документы:** настройка [РФ](инструкция-администратора-РФ.md) / [КЗ](инструкция-администратора-КЗ.md), [описание пакетов](описание-пакетов-обмена-контрагентами.md).

---

## 1. Как устроено, в двух словах

- **С портала в 1С** приходят новые контрагенты и все изменения. Портал присылает карточку целиком, 1С её создаёт или обновляет.
- **Из 1С на портал** уходит только **новый** контрагент, заведённый бухгалтером, через 5 минут после создания. Правки уже существующих карточек на портал не уходят: менять контрагента нужно на портале.
- Получив карточку из 1С, портал присылает её обратно со своими номерами. После этого карточка в 1С связана с порталом.

Что значат слова в этом документе:

| Слово | Значение |
|---|---|
| **Пакет** | одно сообщение в Kafka: карточка контрагента или статус |
| **Статус** | ответ на пакет: «взял в работу» (`started`), «готово» (`completed`), «ошибка» (`failed`) |
| **Консьюмер** | фоновый процесс 1С, который читает пакеты из Kafka |
| **Внешний ID** | номер карточки на портале. Хранится в карточке контрагента, счёта, договора и организации |
| **Код ошибки** | короткое английское имя причины, например `DUPLICATE_CONFLICT`. Список — в §5 |

## 2. Где что смотреть

| Что | Где в 1С |
|---|---|
| Что пришло с портала и чем закончилось | **Kafka → Работа с данными → (Kafka) Журнал этапов** |
| Причина ошибки по пакету с портала | **Kafka → Работа с данными → (Kafka) Исходящие статусы**, строка с типом `failed`, поле содержимого |
| Карточки, отправленные из 1С | **Все функции → Обработки → (Kafka) Рабочий стол**, вкладка **Исходящие снимки** |
| Какой была карточка до изменения с портала | **Kafka → Работа с данными → (Kafka) Аудит снимков** |
| Пакеты, которые не удалось разобрать | **Kafka → Работа с данными → (Kafka) Карантин** |
| Работают ли консьюмеры | **Все функции → Стандартные → Журнал регистрации**, событие **«Интеграция Kafka. Consumer»** |

Содержимое пакетов видно только пользователю с ролью **(Kafka) Диагностика обмена**.

**Как читать журнал этапов.** Каждый пакет с портала проходит этапы:

```text
received → started → completed        всё хорошо
received → started → failed           ошибка, причина в Исходящих статусах
received → filtered_out               пакет не для этой базы или от самой 1С — это нормально
```

## 3. Если пришли с вопросом

### «Контрагент с портала не появился в 1С»

1. Найдите пакет в **Журнале этапов** по времени, когда на портале создали карточку.
2. Дальше по тому, что нашли:

| Что нашли | Что это значит | Что делать |
|---|---|---|
| Пакета нет совсем | 1С не читает Kafka | §4: проверьте, работают ли консьюмеры |
| `filtered_out` | пакет адресован другой базе (`organization-id` чужой) | уточните на портале, для какой организации создан контрагент |
| `failed` | 1С не приняла карточку | откройте статус в **Исходящих статусах**, по коду найдите действие в §5 |
| `started` без продолжения больше 10 минут | обработка зависла или ждёт головного контрагента | журнал регистрации; если через 3 попытки не прошло, будет `failed` |
| `completed`, а карточки не видно | карточку нашли и обновили существующую | ищите по ИНН / БИН или по «Внешнему ID» |

### «Контрагент из 1С не появился на портале»

Откройте **Рабочий стол → Исходящие снимки** и найдите карточку.

| Состояние | Что значит | Что делать |
|---|---|---|
| Строки нет | исходящий обмен выключен, или карточку создал не пользователь, а сам обмен | проверьте «Исходящий обмен включен» в настройках контура |
| Ожидает | 5 минут ещё не прошли | подождать |
| Ожидает, и в «Диагностике» есть текст | нет связи с Kafka | проверить Kafka; 1С повторит отправку сама |
| Ожидает больше 10 минут без текста ошибки | не работает задание публикации | включить **«Задание публикации исходящих снимков»** |
| Отправляется | идёт отправка | подождать |
| Отправлен | пакет в Kafka, портал ещё не ответил | спросить портал |
| Начат / Завершён | портал принял | если на портале карточки нет — вопрос к порталу |
| Ошибка | портал отказал, или 1С не смогла собрать пакет | прочитайте «Диагностику», исправьте, нажмите **«Повторить отправку»** (§6) |
| Заменён | по записи уже сделан повтор | смотрите новую запись |

Тот же список без кнопки повтора открывается через **Все функции → Регистры сведений → (Kafka) Исходящие снимки**:

![Исходящие снимки и их состояния](img/11-outgoing.png)

Самая частая ошибка — `contracts[0].organization`: у договора не указана организация, или у организации не заполнен «Внешний ID». Исправьте и нажмите «Повторить отправку».

### «Счёт или договор пропал / помечен на удаление»

С портала всегда приходит карточка целиком. Если счёта или договора в ней нет, 1С ставит на нём **пометку удаления**, но не удаляет.

- Элемент удалили на портале — так и должно быть.
- Элемент завели в 1С **после** отправки карточки на портал — портал о нём не знает. Сделайте «Повторить отправку» по этой карточке, затем снимите пометку или дождитесь, когда портал пришлёт элемент обратно.

### «Появился дубль контрагента»

1С ищет карточку сначала по номеру портала, потом по uid и только затем по ИНН / БИН. Дубль обычно значит, что карточку завели вручную до того, как она пришла с портала.

Объедините дубли типовой обработкой. Оставьте у основной карточки «Внешний ID» и «Внешний UID».

### «Правку в 1С не видно на портале»

Так и задумано: из 1С уходит только новый контрагент. Правки делают на портале.

## 4. Проверка, что обмен работает

| Что проверить | Как | Норма |
|---|---|---|
| Консьюмеры запущены | **Журнал регистрации**, событие «Интеграция Kafka. Consumer» | после каждого запуска базы есть «Старт подписки» для обеих групп: РФ `…1c.bp.rf` и `…1c.bp.rf.exchange`, КЗ `…1c.bp.kz` и `…1c.bp.kz.exchange` |
| Регламентные задания | **Администрирование → Обслуживание → Регламентные операции → Регламентные и фоновые задания** | включены «Задание мониторинга консьюмеров», «Задание публикации исходящих снимков», «Задание очистки хранения». Последний запуск без ошибки |
| Пакеты идут | **Журнал этапов** | есть свежие записи, если портал что-то отправлял |
| Нет зависших отправок | **Исходящие снимки**, отбор по состоянию «Ожидает» | нет записей старше 10 минут |
| Нет ошибок | **Исходящие снимки** и **Журнал этапов**, отбор «Ошибка» / `failed` | каждая ошибка разобрана |

Если консьюмеры не запущены:

1. Проверьте, включено ли «Задание мониторинга консьюмеров».
2. Проверьте карточки в **Kafka → Справочники → (Kafka) Консьюмеры**: стоит «Активен», а слева от флажка видна ссылка с расписанием.
3. **Файловая база:** откройте хотя бы один сеанс 1С. Без сеанса регламентные задания не работают. Даже с сеансом два консьюмера работают по очереди: если идут только карточки, а статусы портала нет, это ограничение файловой базы. Решение — клиент-серверная база.
4. Ошибка подключения к Kafka — проверьте пароль: переменная `KAFKA_PASSWORD` или файл `C:\Temp\kafka-pass.txt` на компьютере, где работает 1С.

**Предупреждение «Смещение в учёте … расходится со смещением группы …»** в журнале регистрации значит, что позиция чтения в 1С отличалась от Kafka. Например, базу восстановили из копии. 1С сама продолжает читать с позиции Kafka, делать ничего не нужно. Но пакеты, которые за это время прочитал кто-то другой той же группой, в эту базу не попали. Если это важно, попросите портал прислать их заново.

## 5. Коды ошибок и что делать

| Код | Что случилось | Что делать |
|---|---|---|
| `REQUIRED_FIELD_MISSING` | не заполнено обязательное поле. В тексте указано, какое | исправить на портале |
| `INVALID_FORMAT` | неверный формат, чаще всего ИНН / БИН | исправить на портале. В базе КЗ это нормальный ответ на российскую карточку, разосланную всем |
| `REFERENCE_NOT_FOUND` | в 1С нет того, на что ссылается пакет, обычно организации договора | у организации в 1С должны быть «Внешний ID» и тот же uid, что на портале |
| `DUPLICATE_CONFLICT` | в 1С несколько подходящих карточек | объединить дубли, затем повторить обработку (§6) |
| `HEAD_CONTRAGENT_NOT_FOUND` | нет головного контрагента для обособленного подразделения | попросить портал прислать головного, затем повторить обработку |
| `UNSUPPORTED_VERSION` | версия пакета не разрешена | в настройках контура «Допустимые версии» = `1.0.*;1.1.*` |
| `INTERNAL_ERROR` | ошибка внутри 1С | журнал регистрации; 1С повторит сама до 3 раз |

При любой ошибке карточка в 1С не меняется.

## 6. Повторы

**Повторить отправку карточки из 1С.** **Рабочий стол → Исходящие снимки**, выделите строку, нажмите **«Повторить отправку»**. Пакет соберётся заново из текущей карточки и уйдёт как новый: портал увидит его как новый запрос. Старая запись получит состояние «Заменён». Кнопка работает для состояния «Ошибка» и для «Ожидает» с ошибкой связи.

**Повторить обработку пакета с портала.** Сама 1С после окончательной ошибки не повторяет. Есть два способа:

- попросить портал прислать карточку заново — проще всего;
- выполнить в консоли кода `KFK_АдминистрированиеОбменаСервер.ПовторитьFailed("RF", "<id пакета>")`, для базы КЗ — `"KZ"`. Номер пакета есть в Журнале этапов.

---

## 7. Чего обмен не делает

- Не отправляет на портал правки существующих карточек и не выгружает старые карточки.
- Не догоняет счета и договоры, добавленные после отправки: нужна «Повторить отправку».
- Не удаляет счета и договоры, только помечает на удаление.
- Не передаёт документы, только контрагентов.
