# Обмен контрагентами: описание пакетов

**Обновлено:** 11.11.2026
**Для кого:** интеграторы и команда портала. Администратору 1С этот документ нужен только при разборе спорных случаев.
**Настройка обмена:** [РФ](инструкция-администратора-РФ.md), [КЗ](инструкция-администратора-КЗ.md). **Сопровождение:** [сопровождение-обмена-контрагентами.md](сопровождение-обмена-контрагентами.md).
**Схемы JSON:** `src/cfe/ИнтеграцияApacheKafka/contract/counterparty/` (версии `1.0.0` и `1.1.0`).

Откуда взяты примеры:

- §3 и §4 — примеры из технического задания;
- остальные — пакеты из тестового прогона 11.11.2026. Номера и названия в них тестовые.

---

## 1. Какие пакеты ходят

| № | Откуда → куда | Топик | `type` | Раздел |
|---|---|---|---|---|
| 1 | Портал → 1С | `contragents` | `contragent_created` — новая карточка | [§3](#3-портал--1с-новая-карточка) |
| 2 | Портал → 1С | `contragents` | `contragent_updated` — изменение карточки | [§4](#4-портал--1с-изменение-карточки) |
| 3 | 1С → портал | `contragents.exchange` | `contragent_exchange_started` / `_completed` / `_failed` на пакеты 1 и 2 | [§5](#5-1с--портал-статусы-обработки) |
| 4 | 1С → портал | `contragents` | `contragent_created` — карточка, заведённая в 1С | [§6](#6-1с--портал-новая-карточка-из-1с) |
| 5 | Портал → 1С | `contragents.exchange` | статусы портала на пакет 4 | [§7](#7-портал--1с-статусы-на-карточку-из-1с) |
| 6 | Портал → 1С | `contragents` | `contragent_updated` с номерами портала — ответ на пакет 4 | [§8](#8-портал--1с-номера-портала-для-карточки-из-1с) |

Как это выглядит во времени для карточки, заведённой в 1С:

```text
1С        ── contragent_created (без id, с uid) ──────────▶  портал      пакет 4
1С  ◀──── contragent_exchange_started / completed ──────── портал      пакет 5
1С  ◀──── contragent_updated (id + uid) ─────────────────── портал      пакет 6
1С        ── contragent_exchange_started / completed ────▶  портал      пакет 3
```

## 2. Заголовки

| Заголовок | Что значит | Пример |
|---|---|---|
| `sender` | кто отправил: `corp` — портал, `1c-rf` — база РФ, `1c-kz` — база КЗ | `corp` |
| `type` | вид пакета | `contragent_created` |
| `version` | версия формата: `1.0.x` или `1.1.x` | `1.1.0` |
| `id` | уникальный номер пакета (UUID). Повтор с тем же `id` второй раз не применяется | `4baf2094-2c66-4c94-ba08-53425e64936b` |
| `correlation-id` | номер «разговора»: статусы несут тот же номер, что и пакет, на который отвечают | `4431e72d-003e-405d-97e8-ce566c0a828d` |
| `timestamp-ms` | время отправки. Несмотря на имя, это Unix-время **в секундах**, ровно 10 цифр | `1794408998` |
| `organization-id` | код организации-получателя: `1` — РФ, `5` — КЗ. Если заголовка нет, пакет получают обе базы | `1` |

**Ключ сообщения** (key) в топике `contragents` равен `uid` карточки.

### Значения полей карточки

| Поле | Значения |
|---|---|
| `id` | номер карточки на портале (целое). В пакете из 1С его нет |
| `uid` | UUID карточки. Обязателен в пакете из 1С |
| `type_entity` | `legal` — юрлицо, `sole_proprietor` — ИП, `physical_person` — физлицо, `legal_outside` — нерезидент |
| `reg_number` | ИНН для РФ, БИН / ИИН для КЗ |
| `addresses[].type` | `actual` — фактический, `legal` — юридический, `postal` — почтовый |
| `contracts[].type` | `realization` — с покупателем, `purchase` — с поставщиком |
| `contracts[].organization` | организация договора, всегда `id` и `uid` |
| `head_contragent` | головной контрагент обособленного подразделения (`is_separate: true`) |
| `bank_accounts[]`, `contracts[]` | у каждого элемента `id`, `uid` или оба |

<a id="4-портал--1с-изменение-карточки"></a>

## 4. Портал → 1С: изменение карточки

Топик `contragents`, `type` = `contragent_updated`. Пакет несёт **полный** снимок карточки. Счета и договоры, которых нет в пакете, 1С помечает на удаление. Если элемент снова придёт в пакете, пометка снимается.

```json
headers:
{ "sender": "corp", "type": "contragent_updated", "version": "1.0.0",
  "id": "7c1a0d2e-915b-11f1-9f6a-000c29226f4b",
  "correlation-id": "5ce6cd28-bec9-45cd-ab8b-e717ac180139",
  "timestamp-ms": "1789707183", "organization-id": "1" }
value:
{
  "id": 177513,
  "uid": "1742217c-915b-11f1-9f6a-000c29226f4b",
  "name": "Обособленное подразделение г. Костомукша",
  "type_entity": "legal",
  "reg_number": "2901243789",
  "kpp": "100445001",
  "is_separate": true,
  "head_contragent": { "id": 15454, "uid": "463a9c05-35dc-11ea-8efd-0050560114f9" },
  "addresses": [
    { "type": "legal", "address": "г. Костомукша, шоссе Горняков, участок 191, 186931" }
  ],
  "bank_accounts": [],
  "contracts": [
    { "id": 59556, "uid": "fc81cf22-fd85-4ab2-997f-dcf2ccfb9ca5",
      "number": "б/н", "name": "дог. №б/н от 01.01.2026", "date": "01.01.2026 00:00:00",
      "type": "realization",
      "organization": { "id": 1, "uid": "a4820bb1-4def-11e4-8215-0050569c4221" } }
  ]
}
```

### Как 1С находит карточку

1. По `id` (поле «Внешний ID» в 1С).
2. По `uid` (поле «Внешний UID» или внутренний идентификатор карточки, если она создана в 1С).
3. Только если по `id` и `uid` ничего не найдено — по ИНН + КПП (РФ) или БИН / ИИН (КЗ).

Ошибка `DUPLICATE_CONFLICT` возникает в двух случаях:

- `id` и `uid` указывают на разные карточки;
- при поиске по регистрационному номеру нашлось больше одной карточки.

Дубли по ИНН не мешают, если карточка нашлась по `id` или `uid`.

<a id="5-1с--портал-статусы-обработки"></a>

## 5. 1С → портал: статусы обработки

Топик `contragents.exchange`. На каждый принятый пакет 1С отвечает двумя статусами: сначала `started`, затем `completed` или `failed`. `correlation-id` берётся из пакета портала, а `version` у статусов 1С — `1.0.0`.

**Принят в работу:**

```json
headers:
{ "sender": "1c-rf", "type": "contragent_exchange_started", "version": "1.0.0",
  "id": "a11631a8-e458-40a6-a4dc-50e93993edda",
  "correlation-id": "a1000001-0000-4000-8000-000000000017",
  "timestamp-ms": "1794410359" }
value:
{ "id": 7700001, "uid": "670c8bc6-dddf-11f1-9953-010101010000" }
```

**Готово:** то же, `type` = `contragent_exchange_completed`.

**Ошибка: организации договора нет в 1С** (база КЗ):

```json
headers:
{ "sender": "1c-kz", "type": "contragent_exchange_failed", "version": "1.0.0",
  "id": "f94619f0-b2a3-4619-87cb-3ffd7a3ebc33",
  "correlation-id": "b2000001-0000-4000-8000-000000000031",
  "timestamp-ms": "1794412496" }
value:
{
  "id": 7700005,
  "uid": "b2000001-0000-4000-8000-0000000000a5",
  "messages": [
    { "code": "REFERENCE_NOT_FOUND",
      "path": "contracts[0].organization.uid",
      "message": "Не найдена организация с uid b2000001-0000-4000-8000-0000000000c5" }
  ]
}
```

**Ошибка: российский ИП пришёл без `organization-id`, база КЗ не приняла номер:**

```json
value:
{ "id": 7700004, "uid": "b2000001-0000-4000-8000-0000000000a4",
  "messages": [ { "code": "INVALID_FORMAT", "path": "reg_number",
                  "message": "Введенный БИН / ИИН некорректен." } ] }
```

### Коды ошибок

| Код | Что случилось | Окончательная? |
|---|---|---|
| `REQUIRED_FIELD_MISSING` | не заполнено обязательное поле | да |
| `INVALID_FORMAT` | неверный формат, например ИНН/БИН не проходит проверку | да |
| `REFERENCE_NOT_FOUND` | ссылка на то, чего нет в 1С: организация договора, страна и т. п. | да |
| `DUPLICATE_CONFLICT` | несколько подходящих карточек в 1С (§4) | да |
| `HEAD_CONTRAGENT_NOT_FOUND` | головной контрагент не найден | да, после 3 попыток |
| `UNSUPPORTED_VERSION` | версия пакета не разрешена в настройках базы | да |
| `INTERNAL_ERROR` | ошибка внутри 1С | нет: 1С повторит до 3 раз |

Если пакет закончился ошибкой, карточка в 1С не меняется: ни частичной записи, ни номеров портала.

## 6. 1С → портал: новая карточка из 1С

Топик `contragents`. 1С отправляет пакет через 5 минут после создания карточки, чтобы в него попали счета и договоры, введённые сразу. Поля `id` нет — портал карточку ещё не знает. Есть `uid` у карточки, у каждого счёта и у каждого договора. Договор отправляется только с организацией, у которой есть номер портала.

```json
headers:
{ "sender": "1c-kz", "type": "contragent_created", "version": "1.1.0",
  "id": "df931f1f-ffc6-4fcb-9062-9ff06019ca8c",
  "correlation-id": "c8c277a0-b6cc-464c-a8fd-81ebefc899cf",
  "timestamp-ms": "1794411370", "organization-id": "5" }
key: 56786ee1-53a5-4453-ae88-54356185790e
value:
{
  "uid": "56786ee1-53a5-4453-ae88-54356185790e",
  "name": "ТОО Тест Исходящий КЗ 1",
  "name_short": "ТОО Тест Исходящий КЗ 1",
  "type_entity": "legal",
  "reg_number": "5001007311",
  "is_provider": false,
  "is_client": false,
  "is_transporter": false,
  "is_other_relationship": false,
  "is_separate": false,
  "bank_accounts": [
    { "uid": "6d60bf96-e811-4f93-bbeb-f33b62da32d9",
      "number": "KZ86125KZT1001377001", "bic": "00000000022",
      "name": "Тест КЗ счёт 1", "is_default": false }
  ],
  "contracts": [
    { "uid": "09251b98-399f-46de-8ce2-b90a49e0ccd3",
      "number": "КЗ-ТЕСТ-1", "name": "Договор Тест КЗ 1", "type": "realization",
      "organization": { "id": 5, "uid": "332fae60-beeb-11ec-ab7c-005056afcb0f" } }
  ]
}
```

> В тестовом прогоне этот пакет ушёл с договором без организации. Так вела себя версия до исправления, теперь такой пакет не отправляется. Здесь договор показан в нынешнем виде.

Пакет из базы РФ выглядит так же: `sender` = `1c-rf`, `organization-id` = `1`, в карточке ещё `kpp`.

<a id="7-портал--1с-статусы-на-карточку-из-1с"></a>

## 7. Портал → 1С: статусы на карточку из 1С

Топик `contragents.exchange`. Портал отвечает с `sender` = `corp` и тем же `correlation-id`, что у пакета из §6.

```json
headers:
{ "sender": "corp", "type": "contragent_exchange_started", "version": "1.1.0",
  "id": "b2000001-0000-4000-8000-000000000001",
  "correlation-id": "c8c277a0-b6cc-464c-a8fd-81ebefc899cf",
  "timestamp-ms": "1794411400" }
value:
{ "id": 7700002, "uid": "56786ee1-53a5-4453-ae88-54356185790e" }
```

Затем портал присылает `contragent_exchange_completed` с тем же телом. При отказе — `contragent_exchange_failed` с массивом `messages`, как в §5. Можно использовать короткие типы `started` / `completed` / `failed`.

Статус, который старее уже полученного (например `started` после `completed`), 1С игнорирует.

## 8. Портал → 1С: номера портала для карточки из 1С

Топик `contragents`, `type` = `contragent_updated`. Портал возвращает ту же карточку, теперь с `id` рядом с `uid`: у карточки, у каждого счёта и у каждого договора. 1С находит свою карточку по `uid` и записывает номера. Вторая карточка не создаётся. На этот пакет 1С отвечает статусами из §5.

  "id": "b2000001-0000-4000-8000-000000000012",
  "correlation-id": "b2000001-0000-4000-8000-000000000013",
  "timestamp-ms": "1794411500", "organization-id": "5" }
key: 56786ee1-53a5-4453-ae88-54356185790e
value:
{
  "id": 7700002,
  "uid": "56786ee1-53a5-4453-ae88-54356185790e",
  "name": "ТОО Тест Исходящий КЗ 1",
  "name_short": "ТОО Тест Исходящий КЗ 1",
  "type_entity": "legal",
  "reg_number": "5001007311",
  "is_provider": false,
  "is_client": false,
  "is_transporter": false,
  "is_other_relationship": false,
  "is_separate": false,
  "bank_accounts": [
    { "id": 7700102, "uid": "6d60bf96-e811-4f93-bbeb-f33b62da32d9",
      "number": "KZ86125KZT1001377001", "bic": "00000000022",
      "name": "Тест КЗ счёт 1", "is_default": false }
  ],
  "contracts": [
    { "id": 7700202, "uid": "09251b98-399f-46de-8ce2-b90a49e0ccd3",
      "number": "КЗ-ТЕСТ-1", "name": "Договор Тест КЗ 1", "type": "realization",

## 9. Что 1С пропускает без ответа

| Пакет | Почему |
|---|---|
| `organization-id` чужой базы или неизвестный | пакет не для этой базы |
| `sender` = `1c-rf` / `1c-kz` в `contragents` | свой пакет или пакет соседней базы 1С |
| Статус в `contragents.exchange` не от `corp` | это статусы баз 1С, портал их читает сам |
| Статус портала с неизвестным `correlation-id` | 1С такую карточку не отправляла |
| Статус старее уже полученного | повтор |
| Пакет с `id`, который уже обработан | повтор |
| Пакет без заголовков или с пустым телом в `contragents.exchange` | мусор, пропускается без остановки чтения |

## 10. Повторы

| Ситуация | Что происходит |
|---|---|
| Сбой связи при отправке из 1С | 1С повторяет с теми же `id` и `correlation-id` |
| Администратор 1С нажал «Повторить отправку» | **новые** `id` и `correlation-id`; портал начинает новый цикл |
| Портал прислал тот же `id` повторно | 1С не применяет его второй раз |
