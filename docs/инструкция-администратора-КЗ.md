# Инструкция администратора: обмен контрагентами (контур КЗ)

**Last Updated:** 2026-11-01  
**Аудитория:** администратор 1С / интегратор  
**Контур:** Бухгалтерия для Казахстана + расширение `ИнтеграцияApacheKafka`  
**Связанные артефакты:** [README.md](README.md), [инструкция-администратора-РФ.md](инструкция-администратора-РФ.md), [extension-contours.md](extension-contours.md)

Пароли и ключи Kafka в этот документ **не входят**. Ниже — отличия КЗ и минимальный чек-лист; подробные шаги брокера, секрета, ролей, replay и диагностики — по аналогии с инструкцией РФ (§3–6), с подстановкой контура **KZ** и базы **БП_КЗ**.

## 1. Отличия от РФ

| | РФ | КЗ |
|---|---|---|
| Исходники CFE | `src/cfe/ИнтеграцияApacheKafka` | `src/cfe_bp_kz/ИнтеграцияApacheKafka` (отдельная поставка, не копия бинарника РФ) |
| База | `БП_РФ`, пользователь Designer `itc` | `БП_КЗ`, пользователь `AI` |
| Публикация / MCP | `http://localhost/Ankas_bp_rf`, `1c-server-direct-ankas` | `http://localhost/Ankas_bp_kz`, `1c-server-direct-ankas-kz` |
| Код контура | `RF`, group `dev.1c.bp.rf`, sender `1c-rf` | `KZ`, group `dev.1c.bp.kz`, sender `1c-kz` |
| Адаптер | `KFK_АдаптерКонтрагентовРФСервер` | `KFK_АдаптерКонтрагентовКЗСервер` |
| Маршрут org | `organization-id=1` → RF | `organization-id=5` → KZ |

Топики те же: вход `contragents`, статусы `contragents.exchange`.

Один файл расширения нельзя загрузить в обе конфигурации: UUID заимствованных объектов различаются (`extension-contours.md`).

## 2. Предпосылки

1. База БП Казахстан с установленной поставкой `ИнтеграцияApacheKafka` из `src/cfe_bp_kz/...` или готового `.cfe`.
2. Топики `contragents` и `contragents.exchange` созданы явно.
3. Компонента Simple Kafka 1C в макете `KFK_Компонента`.
4. Роли `KFK_СервисОбмена`, `KFK_ДиагностикаОбмена` + типовые права входа.
5. В `KFK_МаршрутизацияОрганизаций` активна строка `5 → KZ` (и при необходимости `1 → RF` для чужих пакетов). Меню: **Kafka → Работа с данными**.

| Способ | Где |
|---|---|

## 3. Настройки контура KZ

Регистр `KFK_НастройкиКонтуров`, стартовый профиль **KZ** (dev):

| Поле | Значение |
|---|---|
| `КодКонтура` | `KZ` |
| `Отправитель` | `1c-kz` |
| `ГруппаПотребителя` | `dev.1c.bp.kz` |
| `ТопикВходящий` | `contragents` |
| `ТопикСтатусов` | `contragents.exchange` |
| `КоличествоВоркеров` | `1` |
| `ОжидаемоеЧислоРазделов` | `1` |
| `ДопустимыеВерсии` | `1.0.*` |

Для test/prod смените group на `test.1c.bp.kz` / `prod.1c.bp.kz`.

Секрет Kafka — теми же источниками, что на РФ (`KAFKA_PASSWORD` → файл → хранилище `KFK_KafkaBroker`). Проверка: `KFK_СекретыОкруженияСервер.ПроверитьГотовностьПодключенияKafka()`.

## 4. Автомат (без консоли)

1. Включить регламент **`KFK_ЗаданиеМониторингаКонсьюмеров`** (Использование = да, расписание ~30 с). На dev после 01.11 задание уже включалось.
2. Создать карточку `KFK_Консьюмеры` (на пустой базе после клона её может не быть): брокер, топик `contragents`, **Активен**, **расписание на элементе**, group как в профиле KZ (`dev.1c.bp.kz`), `enable.auto.commit=false`.
3. Профиль `KFK_НастройкиКонтуров` для **KZ** заполнен.
4. Файловая ИБ — держать открытым сеанс 1С.
5. Проверка: `KFK_КонсьюмерЖизненныйЦиклСервер.Состояние("KZ")` → `active≥1`.
6. Остановка: `KFK_КонсьюмерЖизненныйЦиклСервер.Остановить("KZ")`.

Форма «Слушать» на обработке консьюмера — только peek; бизнес-цикл — серверный `СлушатьСообщения`.

Мониторинг КЗ при пустом list-topics с брокера использует `ОжидаемоеЧислоРазделов` из настроек контура KZ.

## 5. Маршрутизация на контуре KZ

| Заголовок `organization-id` | Поведение KZ |
|---|---|
| `5` | Принят |
| пустой / отсутствует | Широковещание — принят |
| `1` | Чужой → `filtered_out`, без статуса в exchange |
| неизвестный / неактивный | Skip без статуса |

## 6. Ошибки детей → Failed

`ПрименитьСнимокКЗ` пробрасывает бизнес-коды из договоров/счетов (`REFERENCE_NOT_FOUND` и др.) в terminal Failed, без обёртки в retryable `INTERNAL_ERROR`.

Отсутствующие в снимке счета и договоры **не удаляются физически**: ставится `ПометкаУдаления`. Повторное появление в снимке снимает пометку.

Где смотреть причину:

- Kafka `contragents.exchange`, тип Failed → `messages[].code` / `path`;
- ИБ: `KFK_ИсходящиеСтатусы` seq20 `Payload`; процесс в `KFK_ПроцессыОбмена`.

Replay failed:

```bsl
KFK_АдминистрированиеОбменаСервер.ПовторитьFailed("KZ", "<message-id>")
```

Новый message id — только с явным подтверждением (см. инструкцию РФ §4.4).

## 7. Типовые проверки

| Проверка | Как |
|---|---|
| Готовность Kafka | `ПроверитьГотовностьПодключенияKafka` / настройки брокера |
| Фон | `Состояние("KZ")` |
| Стоп | `Остановить("KZ")` |
| Метрики | `KFK_АдминистрированиеОбменаСервер.СобратьМетрикиКонтура("KZ")` |
| Роли | `KFK_СервисОбмена`, `KFK_ДиагностикаОбмена` + типовой вход |
| COM-приёмка снимка | `build/verification/task-10.2-kz-snapshot/` → ожидание `KZ_VERDICT=PASS` |
