# Настройка обмена контрагентами с порталом (БП РФ)

**Обновлено:** 11.11.2026
**Для кого:** администратор 1С, который настраивает обмен в базе «Бухгалтерия предприятия» РФ. Делается один раз.
**Что дальше:** работа после настройки описана в [сопровождении](сопровождение-обмена-контрагентами.md), форматы сообщений — в [описании пакетов](описание-пакетов-обмена-контрагентами.md). Для базы Казахстана есть [своя инструкция](инструкция-администратора-КЗ.md).

Паролей в документе нет.

---

## Как это работает

```text
                 ┌────────────────────── Kafka ──────────────────────┐
  Портал  ──▶   │ contragents           карточки контрагентов          │   ──▶  1С
  Портал  ◀──   │ contragents.exchange  ответы: «принял», «готово»,    │   ◀──  1С
                │                       «ошибка»                       │
                 └───────────────────────────────────────────────────┘
```

- Портал присылает в 1С новых контрагентов и изменения. 1С заводит или обновляет карточку и отвечает, получилось ли.
- Когда бухгалтер заводит нового контрагента в 1С, через 5 минут 1С отправляет его на портал. Портал отвечает и присылает карточку обратно со своими номерами.
- Правки уже существующих карточек из 1С на портал **не** уходят. Хозяин карточки — портал.

Слова, которые встретятся ниже:

| Слово | Что это |
|---|---|
| **Kafka** | сервер-посредник, через который портал и 1С обмениваются сообщениями |
| **Брокер** | адрес сервера Kafka |
| **Топик** | «почтовый ящик» в Kafka. Их два: `contragents` и `contragents.exchange` |
| **Группа** | имя, под которым 1С читает топик. Kafka по нему помнит, что 1С уже прочитала |
| **Консьюмер** | фоновый процесс 1С, который читает топик. Нужно два: для карточек и для ответов портала |
| **Контур** | настройки обмена для одной базы. У базы РФ код контура `RF` |
| **Внешний ID** | номер объекта на портале, хранится в карточке 1С |

## Что подготовить заранее

| Что | У кого |
|---|---|
| Адрес сервера Kafka (`хост:порт`), логин и пароль | администратор Kafka |
| Созданы топики `contragents` и `contragents.exchange` | администратор Kafka |
| Доступ на чтение и запись в оба топика и на чтение для групп `dev.1c.bp.rf` и `dev.1c.bp.rf.exchange` | администратор Kafka |
| Номер вашей организации на портале (для РФ обычно `1`) | команда портала |
| Файл расширения `IntegracijaApacheKafka-rf.cfe` | [GitHub, папка `dist`](https://github.com/DmitrySkrypkin/1c-kafka-counterparties/tree/main/dist) |

В тестовой и рабочей среде группы называются `test.1c.bp.rf…` и `prod.1c.bp.rf…`. Замените `dev` во всех шагах.

**Тип базы.** Для постоянной работы нужна **клиент-серверная** база. В файловой базе два консьюмера в одном сеансе работают по очереди, поэтому ответы портала могут не читаться. Кроме того, обмен идёт, только пока открыт хотя бы один сеанс 1С.

## Шаг 1. Установите расширение

1. Конфигуратор → **Конфигурация → Расширения конфигурации** → **Добавить**, выберите `IntegracijaApacheKafka-rf.cfe`.
2. Нажмите **Обновить конфигурацию базы данных** (F7).

✔ **Проверка:** в 1С появился раздел **Kafka**. В нём три группы команд: «Работа с данными», «Справочники», «Сервис».

![Раздел Kafka](img/01-kafka-section.png)

Файл для Казахстана (`…-kz.cfe`) в базу РФ не встанет.

## Шаг 2. Выдайте роли

| Кому | Роль |
|---|---|
| Пользователь, от имени которого работают регламентные задания | **(Kafka) Сервис обмена** |
| Администраторы, которые разбирают ошибки | **(Kafka) Диагностика обмена** |

Эти роли не дают права входа в базу. Пользователю нужен ещё обычный профиль доступа.

## Шаг 3. Сохраните пароль Kafka

На компьютере, где работает 1С (для клиент-серверной базы — на сервере 1С), сделайте **одно** из двух:

- создайте переменную среды Windows **`KAFKA_PASSWORD`** со значением пароля;
- **или** создайте файл `C:\Temp\kafka-pass.txt` с одной строкой `pass: ваш_пароль`. Другое место для файла задаётся переменной среды `KAFKA_PASSWORD_FILE`.

После создания переменной среды перезапустите службу сервера 1С или клиент.

Пароль **не** вписывайте в карточку брокера и в настройки: там его увидят все пользователи.

## Шаг 4. Заведите брокер

**Kafka → Справочники → Брокеры → Создать.**

| Поле | Что вписать |
|---|---|
| **Наименование** | любое, например `Kafka` |
| **Адрес брокера** | `хост:порт` от администратора Kafka |
| Вкладка **Параметры подключения (SASL, SSL…)** | строки «ключ = значение» **без пароля**, например `security.protocol` = `SASL_PLAINTEXT`, `sasl.mechanism` = `SCRAM-SHA-512`, `sasl.username` = логин. Точный набор даст администратор Kafka |

Нажмите **Записать**.

![Карточка брокера: адрес и параметры подключения без пароля](img/02-broker.png)

✔ **Проверка:** на вкладке **Топики** есть `contragents` и `contragents.exchange`. Если вкладка пустая, значит нет связи или неверен пароль: вернитесь к шагу 3.

![Вкладка «Топики» карточки брокера](img/03-broker-topics.png)

## Шаг 5. Проверьте настройки контура

**Kafka → Работа с данными → (Kafka) Настройки контуров.** Откройте запись с кодом контура **РФ**.

Если записи нет, **не создавайте её вручную**: значения по умолчанию подставляются, только когда записи нет совсем. Запись появится сама при первом запуске консьюмера. Сделайте шаги 6–9 и вернитесь к этому шагу.

Проверьте эти поля, остальные не трогайте:

| Поле | Значение |
|---|---|
| Отправитель | `1c-rf` |
| Группа потребителя | `dev.1c.bp.rf` |
| Группа потребителя статусов портала | `dev.1c.bp.rf.exchange` |
| Топик входящий | `contragents` |
| Топик статусов | `contragents.exchange` |
| **Допустимые версии** | **`1.0.*;1.1.*`** — обязательно исправьте, по умолчанию стоит `1.0.*` |
| Исходящий обмен включен | пока **нет**, включается в шаге 10 |
| Задержка отправки секунд | `300` |
| Версия исходящего контракта | `1.1.0` |

Почему версии важны: ответ портала на карточку из 1С приходит в версии `1.1.0`. Без `1.1.*` 1С его отклонит, и карточка не свяжется с порталом.

![Настройки контура: выделены «Допустимые версии» и поля исходящего обмена](img/04-settings.png)

На снимке тестовая база: исходящий обмен уже включён, а задержка уменьшена до 60 секунд. В рабочей базе задержка — 300.

## Шаг 6. Проверьте маршрутизацию организаций

**Kafka → Работа с данными → (Kafka) Маршрутизация организаций.** Должно быть две строки:

| Код организации | Код контура | Активен |
|---|---|---|
| `1` | РФ | да |
| `5` | Казахстан | да |

![Маршрутизация организаций](img/05-routing.png)

Портал помечает каждое сообщение номером организации. База РФ принимает сообщения с `1`, сообщения с `5` пропускает: они для Казахстана. Сообщения без номера принимают обе базы.

## Шаг 7. Проставьте организации номер портала

Без этого контрагент с договором не уйдёт на портал.

1. **Все функции → Справочники → Организации**, откройте организацию.
2. Если поля **«Внешний ID»** на форме нет: **Ещё → Изменить форму**, найдите «Внешний ID», поставьте флажок, **ОК**.
3. Впишите номер организации на портале и запишите.

## Шаг 8. Создайте два консьюмера

**Kafka → Справочники → Консьюмеры → Создать.** Создайте две карточки:

| Поле | Карточка 1: карточки контрагентов | Карточка 2: ответы портала |
|---|---|---|
| **Наименование** | `RF contragents` | `RF exchange statuses` |
| **Идентификатор** | `dev.1c.bp.rf` | `dev.1c.bp.rf.exchange` |
| **Брокер** | из шага 4 | из шага 4 |
| **Активен** | ✔ | ✔ |
| Вкладка **Топики** | `contragents` | `contragents.exchange` |
| Вкладка **Параметры консьюмера** | `enable.auto.commit` = `false`, `auto.offset.reset` = `latest` | `enable.auto.commit` = `false`, `auto.offset.reset` = `earliest` |
| Вкладка **Дополнительные параметры**, таймаут ожидания | `500` | `500` |
| Ссылка расписания слева от флажка «Активен» | каждый день, повторять каждые 30 секунд | то же |

Две вещи, без которых не заработает:

- **Идентификатор** должен в точности совпадать с группой из шага 5;
- **расписание** должно быть задано, иначе консьюмер не запустится.

`auto.offset.reset` действует только при самом первом запуске группы. `latest` — начать с новых сообщений и не загружать историю топика. `earliest` — прочитать топик с начала. Если нужно загрузить в базу всех контрагентов, которые уже есть в топике, поставьте `earliest` и для карточки 1.

![Карточка консьюмера: идентификатор и ссылка расписания](img/07-consumer.png)

![Вкладка «Параметры консьюмера»](img/08-consumer-params.png)

✔ **Проверка:** в списке консьюмеров две строки, у обеих стоит «Активен».

![Список консьюмеров](img/06-consumers-list.png)

## Шаг 9. Включите регламентные задания

**Администрирование → Обслуживание**, раскройте группу **Регламентные операции**, ссылка **Регламентные и фоновые задания**.

![Обслуживание → Регламентные операции](img/09-maintenance.png)

| Задание | Расписание | Включать |
|---|---|---|
| **Задание мониторинга консьюмеров** — запускает консьюмеры и поднимает упавшие | каждые 30 секунд | сейчас |
| **Задание очистки хранения** — стирает старое содержимое сообщений | раз в сутки, ночью | сейчас |
| **Задание публикации исходящих снимков** — отправляет новых контрагентов из 1С на портал | каждую минуту | в шаге 10 |

Чтобы быстро найти задания, введите в поиске «Задание». Откройте каждое двойным щелчком: укажите пользователя из шага 2, поставьте флажок **«Использование»** и задайте расписание. Включённое задание отмечено галочкой слева.

![Три задания обмена. На снимке включено только задание публикации](img/10-jobs.png)

✔ **Проверка:** через минуту откройте **Все функции → Стандартные → Журнал регистрации** с отбором по событию **«Интеграция Kafka. Consumer»**. Должны появиться две записи «Старт подписки на топики …» — с `group.id=dev.1c.bp.rf` и с `group.id=dev.1c.bp.rf.exchange`.

Если записей нет:

- проверьте шаг 8: «Активен», расписание, идентификатор;
- в файловой базе должен быть открыт сеанс 1С;
- если есть записи с ошибкой подключения, проверьте шаг 3.

## Шаг 10. Включите отправку контрагентов из 1С

Включайте, когда портал подтвердит, что готов принимать контрагентов из 1С.

1. **(Kafka) Настройки контуров**, запись РФ: **«Исходящий обмен включен»** = ✔.
2. Включите **«Задание публикации исходящих снимков»** (шаг 9).

Чтобы остановить отправку, снимите флажок «Исходящий обмен включен».

## Шаг 11. Проверьте обмен

**С портала в 1С.** Попросите команду портала создать тестового контрагента для организации `1`.

✔ Через минуту:

- контрагент есть в справочнике **Контрагенты**, в поле «Внешний ID» номер с портала;
- в **Kafka → Работа с данными → (Kafka) Журнал этапов** есть строки `received` → `started` → `completed`.

**Из 1С на портал.** Заведите тестового контрагента с правильным ИНН, добавьте ему договор с вашей организацией. Подождите 6–7 минут.

✔ В **Все функции → Обработки → (Kafka) Рабочий стол**, вкладка **Исходящие снимки**, у контрагента состояние сначала «Отправлен», потом «Завершён». Ещё через минуту у карточки появится «Внешний ID» с портала.

Тот же список без кнопок есть в **Все функции → Регистры сведений → (Kafka) Исходящие снимки**:

![Исходящие снимки и их состояния](img/11-outgoing.png)

Если что-то пошло не так, смотрите [сопровождение, раздел 3](сопровождение-обмена-контрагентами.md).

## Приложение. Для интегратора

**Все поля настроек контура** и значения по умолчанию:

| Поле | Значение | Смысл |
|---|---|---|
| Количество воркеров | `1` | сколько разделов топика читать параллельно |
| Ожидаемое число разделов | `1` | если в Kafka разделов больше, в журнале будет предупреждение |
| Базовая / максимальная задержка секунд | `60` / `120` | пауза между повторами при временной ошибке |
| Размер пачки | `100` | |
| Срок хранения входящих / исходящих / аудита, дней | `30` / `30` / `90` | после срока стирается содержимое сообщений, сами записи остаются |
| Порог отставания / возраста минут / критический | `100` / `10` / `15` | пороги для метрик |
| Адрес подключения | пусто | метка, не пароль |

**Третий способ хранить пароль** — безопасное хранилище БСП: владелец `KFK_KafkaBroker`, ключ `Пароль`. Записать его можно только из основной конфигурации, расширению запись запрещена.

**Вызовы в консоли кода:**

```bsl
KFK_СекретыОкруженияСервер.ПроверитьГотовностьПодключенияKafka()   // ожидается ok=1, ready=1; пароль в ответ не попадает
KFK_ИсходящиеСнимкиСервер.ОбеспечитьКонсьюмерСтатусовПортала()    // создаёт карточку 2 из шага 8 по настройкам
KFK_КонсьюмерЖизненныйЦиклСервер.Состояние("RF")                   // active>=1 — консьюмер работает
KFK_КонсьюмерЖизненныйЦиклСервер.ЗапуститьКонтур("RF")
KFK_КонсьюмерЖизненныйЦиклСервер.Остановить("RF")
KFK_АдминистрированиеОбменаСервер.СобратьМетрикиКонтура("RF")      // очереди, возраст, число ошибок
```

**Пересборка `.cfe`** из исходников и контрольные суммы: [`dist/README.md`](https://github.com/DmitrySkrypkin/1c-kafka-counterparties/blob/main/dist/README.md).
