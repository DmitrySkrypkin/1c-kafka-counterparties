# Контракт снимка контрагента 1.1.0

Схемы `headers.schema.json` и `body.schema.json` описывают `contragent_created` и `contragent_updated` для входящего потока портала и исходящего снимка из 1С. Каталог `1.0.0` рядом не изменяется.

Отличия от `1.0.0`:

- тело проходит, если есть числовой `id` **или** `uid` (`anyOf`);
- банковский счёт принимает `id` **или** `uid`, как договор;
- обязательность `id` для `sender=corp` и `uid` для отправителя 1С проверяет кодовый валидатор контура (в схеме тела нет заголовков).

Проверка примеров:

```text
python validate_fixtures.py
```

Файл схемы принимает любую minor-версию major 1 (`1.x.y`). Список разрешённых minor по умолчанию — `1.0.*;1.1.*`.

Поле `timestamp-ms` по ТЗ — unix-время в **секундах**, ровно **10** цифр.

## Каталог кодов

Публиковать можно только эти коды. Условие без более точного кода записывается как `INTERNAL_ERROR`.

- `REQUIRED_FIELD_MISSING` — нет обязательного поля или строка `name` пустая либо состоит из пробелов. Путь — само поле.
- `INVALID_FORMAT` — тип, UUID, перечисление, неверный `timestamp-ms` или иной формат не совпали со схемой. Путь — само поле.
- `UNSUPPORTED_VERSION` — major в `version` не входит в настройку контура. Путь `null`.
- `REFERENCE_NOT_FOUND` — нет элемента 1С по ссылке, кроме головного контрагента. Путь — поле ссылки.
- `HEAD_CONTRAGENT_NOT_FOUND` — голова не найдена после трёх попыток. Путь `head_contragent`.
- `DUPLICATE_CONFLICT` — идентификаторы указывают на разные или несколько карточек. Путь `null` либо ключевое поле.
- `INTERNAL_ERROR` — технический сбой записи или удаления. Путь `null`, если ошибка не привязана к полю.

## Путь JSON

Путь в `messages[].path` строится от тела сообщения:

- поле: `name`, `uid`, `timestamp-ms`;
- вложенное поле: `head_contragent.id`, `contracts[0].organization.uid`;
- элемент коллекции: `addresses[0].type`, `bank_accounts[0].id`, `contracts[0]`.

Индекс начинается с нуля. Для заголовка путь равен имени заголовка. Если ошибка не относится к полю, путь равен `null`.
